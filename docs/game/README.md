# Документация по механикам Rust

Справочник о том, как устроены игровые механики Rust, восстановленный по декомпилированному
коду выделенного сервера (`Assembly-CSharp.dll`). Страницы показываются в приложении в разделе
«Документация» (`/#docs`, страница — `/#docs/<id>`).

Источник: сервер Rust (Steam app 258550), скачан 2026-10-16, декомпилирован ILSpy.
Локальная копия исходников: `~/rust-decompiled/server-2026-10-16/src`.

## Как организовано

Две оси, связанные ссылками:

- **Механики** (`kind: mechanic`) — общие алгоритмы: стабильность, распад, урон, сокеты.
- **Объекты** (`kind: object`) — конкретные вещи: стена, шкаф, C4, дверь. Характеристики,
  поведение и ссылки на механики, в которых объект участвует.
- **Таблицы** (`kind: data`, файлы `data-*.md`) — числа из ассетов игры: HP, защита, урон, рецепты.
  Генерируются скриптом, руками не правятся. Как обновить — в `tools/game-data/README.md`.

Каждая страница — один файл `pages/<id>.md`. `id` совпадает с именем файла,
только латиница, цифры и дефис.

## Формат страницы

```markdown
---
id: stability
title: Стабильность
kind: mechanic
group: Здание и шкаф
summary: Одно предложение — суть для списка и поиска.
related: [building-structure, foundation, wall]
code: [StabilityEntity.cs, BuildingBlock.cs]
---

## Кратко
...
```

Поля front matter (одна строка на поле, списки в квадратных скобках):

| Поле | Что это |
|------|---------|
| `id` | Совпадает с именем файла |
| `title` | Заголовок по-русски |
| `kind` | `mechanic`, `object`, `scheme` или `data` |
| `group` | Одна из групп ниже, дословно |
| `summary` | Одно предложение |
| `related` | id связанных страниц |
| `code` | Главные файлы декомпилированного кода |

Группы (порядок в меню):
Строительство · Здание и шкаф · Урон и рейд · Двери и замки · Защита базы · Электричество · Схемы ·
Индустрия · Вода и фермерство · Игрок · Предметы и производство · Оружие и бой · Торговля ·
Транспорт · NPC и животные · Монументы · Мир и события · Сервер и режимы

## Разделы страницы

Механика: `## Кратко`, `## Как работает`, `## Числа и настройки`, `## Нюансы`, `## На практике`, `## Где в коде`.

Объект: `## Кратко`, `## Характеристики`, `## Поведение`, `## Нюансы`, `## На практике`, `## Где в коде`.

Схема (`kind: scheme`, группа «Схемы»): `## Кратко`, `## Схема`, `## Как собрать`, `## Как работает`, `## Числа`, `## Нюансы`, `## Где в коде`.

Раздел можно опустить, если сказать нечего. Можно добавлять свои `###` подразделы.

## Схемы подключения

Блок кода с языком `scheme` рисуется как SVG-схема. Узлы ставятся по координатам, провода разводятся сами.

````markdown
```scheme
node panel 10,20 "Солнечная панель" "до 20 rW" out: Electric Output
node bat 240,20 "Батарея" "малая" in: Power In out: Power Output
node out 240,140 flip "Ящик выхода" in: Industrial In
wire panel.Electric Output -> bat.Power In "20"
```
````

| Строка | Что значит |
|---|---|
| `node id X,Y [w=Ш] [flip] "Название" ["подпись"] in: …, … out: …, …` | Узел с левым верхним углом в X,Y. Ширина подстраивается под текст, `w=` задаёт минимум. Входы слева, выходы справа; `flip` меняет стороны — для ряда, который идёт справа налево |
| `wire a.Порт -> b.Порт ["подпись"]` | Провод (электричество) |
| `pipe a.Порт -> b.Порт ["подпись"]` | Труба с водой |
| `belt a.Порт -> b.Порт ["подпись"]` | Промышленная труба (предметы) |
| `note X,Y "текст"` | Заметка, `\n` — перенос строки |
| `size Ш x В` | Необязательно: минимальный размер холста |

Имена портов пишутся как в игре, пробелы допустимы. Связь вправо рисуется кривой, назад или вниз — обходом
вокруг узлов. Ошибки (нет узла или порта, узлы налезают) ловит тест `src/docs/scheme.test.ts`. Для схемы
шириной больше ~880 колонка документации её уменьшает — лучше раскладывать в несколько рядов.

## Правила содержания

- Ссылка на другую страницу: `[[stability]]` или `[[stability|текст ссылки]]`.
- Каждое число — из кода, с указанием, откуда: константа, поле класса или ConVar
  (`server.xxx`, `decay.xxx`). Если значение задаётся в префабе или ассете и в коде его нет,
  так и написать: «задаётся в префабе».
- Сведения не из кода (опыт игроков, вики) помечать явно: «по данным сообщества, в коде не подтверждено».
- Код упоминать по имени класса и метода (`StabilityEntity.UpdateStability`), без номеров строк.
  Короткий фрагмент кода (до 15 строк) — только если он объясняет лучше слов.
- Античит (`AntiHack`, проверки валидности выстрелов и перемещения) не описываем.
