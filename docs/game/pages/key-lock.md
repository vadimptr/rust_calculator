## Кратко

При установке ключевой замок получает случайный код и сразу запирается. Открыть его может
владелец (тот, кто поставил) и любой игрок, у которого в инвентаре есть ключ с этим кодом.
Ключ — обычный предмет с числом в `instanceData.dataInt`.

## Характеристики

| Параметр | Значение | Откуда |
|----------|----------|--------|
| Код замка | случайное целое от 1 до 99 999 | `OnDeployed`: `Random.Range(1, 100000)` |
| Состояние после установки | заперт | `OnDeployed` → `Lock(deployedBy)` |
| Где ищется ключ | основной инвентарь, пояс, одежда | `PlayerInventory.FindItemsByItemID` |
| Стоимость и время крафта ключа | 25 Wood, 0,1 с (`ItemBlueprint` предмета `door.key`; вручную ключ не крафтится, только через замок) | `RPC_CreateKey` → `CraftItem` |
| Рецепт самого замка | 75 Wood, 15 с, без верстака, известен сразу | [[data-crafting]] |
| Снятие | разрешено (`CanRemove = 1` в префабе `lock.key`) | `BaseLock.RPC_TakeLock` |
| Дистанция | 3 м | `RPC_Server.MaxDistance(3f, CheckParent = true)` |

## Поведение

### Допуск

`HasLockPermission` даёт доступ, если игрок жив и:

- его Steam ID совпадает с `OwnerID` замка, или
- у него есть ключ с `dataInt == keyCode`.

`OnTryToOpen` и `OnTryToClose` пускают тех, у кого есть доступ, а остальных — только если
замок не заперт.

### Изготовление ключа

`RPC_CreateKey` доступен, если замок не заперт, или если у игрока есть доступ. Сервер
проверяет, может ли игрок скрафтить ключ (`CanCraft`), и ставит крафт в очередь с кодом замка.
Первый созданный ключ запирает замок (`firstKeyCreated`).

### Запереть и отпереть

`RPC_Lock` и `RPC_Unlock` — только для тех, у кого есть доступ.

## Нюансы

- **Владелец всегда проходит.** Ключ хозяину не нужен, потерять доступ, потеряв ключ, нельзя.
- **Код замка не меняется.** Его нельзя перевыпустить: однажды скрафченные ключи открывают
  замок навсегда. Отозвать ключ можно только сменив замок.
- **Ключ работает и в одежде.** Поиск идёт по основному инвентарю, поясу и слотам одежды.
- **Флаг «первый ключ» не сохраняется.** `firstKeyCreated` не пишется в сохранение. После
  рестарта создание ключа снова запрёт отпертый замок.
- **Старые замки получают владельца от двери.** Если после загрузки у замка нет `OwnerID`,
  он берётся у родителя (`PostServerLoad`).
- **Снять можно только отпертый.** Как у любого замка (`BaseLock.RPC_TakeLock`).

## На практике

- Ключевой замок годится для одиночки. Для группы удобнее [[code-lock]]: доступ там можно
  отозвать сменой кода.
- Убитый с ключом в инвентаре игрок отдаёт доступ тому, кто подберёт ключ.
