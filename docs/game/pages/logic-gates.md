## Кратко

Логические элементы Rust работают с числами, а не с «да/нет». Выходное значение — это
**максимум** из входов (у AND — только если оба > 0). Сумму даёт только [[combiner|сумматор]].
Все логические элементы потребляют 0.

## Характеристики

| Элемент | Класс | Префаб | Входы | Выход |
|---|---|---|---|---|
| AND | `ANDSwitch` | `andswitch.entity` | A, B (оба основные) | `max(A, B)`, если A > 0 и B > 0, иначе 0 |
| OR | `ORSwitch` | `orswitch.entity` | A, B (оба основные) | `max(A, B)` |
| XOR | `XORSwitch` | `xorswitch.entity` | A, B (оба основные) | `max(A, B)`, если ровно один > 0, иначе 0 |
| RAND | `RANDSwitch` (наследник блокировщика) | `electrical.random.switch.deployed` | Power In (основной), Set, Reset | весь вход питания, если выпало «да», иначе 0 |

HP у всех — 200 (префабы).

## Поведение

### Какой вход «хочет питания»

От этого зависит, какую батарею элемент разряжает (`ElectricBattery.GetDrain`).

| Элемент | `WantsPower` |
|---|---|
| AND | Только сильнейший вход, если оба > 0 (при равенстве — A). Иначе ни один |
| OR | Только сильнейший (при равенстве — A). Ни один, если оба 0. При [[flicker|мерцании]] — оба |
| XOR | Оба, если ровно один вход > 0 |
| RAND | Вход питания — только когда выпало «да» |

### Поиск петель

- **OR**: на каждый вход `IsConnectedTo(this, slot, 8)`. Петля → вход 0. Флага нет.
- **XOR**: то же для входа > 0, плюс флаг `Reserved7` (короткое замыкание).
- **AND**, **RAND**: проверки нет.

Подробнее — [[circuit-loops]].

### XOR после загрузки

У XOR есть флаги `input1Set`/`input2Set`. Пока вход ни разу не обновился после загрузки,
а флаг «на входе есть сигнал» с прошлой сессии стоит, выход 0. Первое обновление флагов
откладывается на 0.1 с (`UpdateFlags_Delayed`). Это защита от ложного импульса при рестарте.

### RAND

```
вход Set (1): каждое новое значение > 0 → бросок: Random.Range(0, 2) == 1  (50 %)
вход Reset (2): значение > 0 → «нет»
выход = (выпало «да») ? вход питания : 0
```

Бросок происходит при каждом изменении значения на Set, даже 5 → 7, без перехода через 0.

## Нюансы

- **AND пропускает максимум.** AND от батареи на 50 и сигнала датчика на 1 выдаст 50. Сигнал
  датчика работает как «разрешение», а мощность идёт с сильного входа.
- **OR не суммирует.** 10 + 10 через OR = 10.
- **Слабая батарея на OR/AND не разряжается**, хотя её сигнал нужен для работы AND.
- **XOR — тоже максимум**, но только когда активен ровно один вход.
- Все входы AND/OR/XOR основные. Поэтому поиск петель и `SendChangedToRoot` проходят через оба.

## На практике

- AND как «ключ»: мощность на A, сигнал разрешения (кнопка, датчик) на B.
- Резерв питания через OR: основная батарея на A, резервная на B. Тратится только та, что
  сильнее. Когда основная сядет (выход 0), OR переключится на резерв.
- RAND — «рулетка» для ловушек и развлечений.
