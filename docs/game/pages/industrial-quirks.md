## Кратко

Здесь собраны места, где код индустрии ведёт себя неожиданно: ошибки, расхождения
с описаниями ConVar и неочевидные правила. Всё — по декомпилированному коду сервера.
Где вывод не следует из кода однозначно, это сказано отдельно.

## Как работает

### Ошибки и расхождения в коде

1. **`server.maxItemStacksMovedPerTickIndustrial` (12) фактически не работает.**
   В `RunConveyor` счётчик перенесённых стопок `num3` объявлен внутри цикла по предметам
   и обнуляется для каждого предмета. Значит, он не превышает 1, и проверка `num3 >= 12`
   никогда не срабатывает. Лимит действует, только если админ выставит ConVar в 1 или меньше.
   Так это выглядит в декомпиляции; теоретически ILSpy мог неточно передать область видимости
   переменной.
2. **Min по категории считается не по тем слотам.** Для записи-предмета остаток в источнике
   считается по выходному диапазону источника. Для записи-категории вызывается
   `GetTotalCategoryAmount(category, range.x, range.y)`, где `range` — **входной диапазон
   получателя**. Пример: ящик → печь (вход 0–2). «Оставить 1000 ресурсов» по категории
   смотрит только слоты 0–2 ящика.
3. **В режиме «Не» сигнал Pass/Fail может залипать.** `CheckIfAnyInputPassesFilters`
   проверяет записи по одной: «есть ли предмет, не совпадающий с *этой* записью». При двух
   разных записях почти любой предмет даёт «да». Затем перенос правильно отбрасывает
   всё совпавшее, список пуст, и `RunConveyor` выходит **до** обновления флагов
   Pass/Fail. Выходы остаются в прежнем состоянии.
4. **`ElectricFurnaceIO` знает «не те» слоты.** Его `InputSlotRange` = 1–2,
   `OutputSlotRange` = 3–5, а у электропечи всего 5 слотов (0–4). Но у IO-части электропечи
   нет промышленных портов, так что этот код мёртвый. Реально работает `BaseOven`
   в режиме `ElectricFurnace` (0–1 / 2–4) через адаптер.
5. **`MaxStackSizePerMove` в коде — 128, а в префабе — 60.** Работает значение префаба.
6. **Порция «по веткам» считается, но не используется.** `ContainerInputOutput.MaxStackSize`
   никто не читает. Делитель — общее число получателей.

### Неочевидные правила

- **Переключать конвейер и крафтер может кто угодно** в 3 м прямой видимости
  (`SvSwitch` проверяет только `IsVisible`). Фильтры конвейера при этом защищены правами
  в шкафу.
- **Открыть крафтер может кто угодно.** `NeedsBuildingPrivilegeToUse = 0`, замка нет.
- **Сортировку адаптера может перенастроить кто угодно** рядом (`UpdatedStorageSettings`).
- **Конвейер сам включается после перебоя питания, крафтер — нет.**
- **Рестарт заканчивает крафт мгновенно** (`IndustrialCrafter.Load` → `CompleteCraft`).
  При этом апгрейды верстака, скорее всего, не применятся: в момент загрузки родитель-верстак
  может быть ещё не привязан, а `CompleteCraft` берёт его через `GetParentEntity`. Это вывод
  из порядка вызовов, напрямую в коде не проверено.
- **Адаптер не тратит заряд батареи.** `ShouldDrainBattery` по умолчанию сравнивает тип IO:
  промышленный адаптер против электрической батареи даёт `false`. Батарея не учитывает
  его 1 единицу в `ElectricBattery.GetDrain`. Конвейер и крафтер переопределяют проверку
  и учитываются, только когда включены.
- **Адаптер работает без питания** — ток нужен только для сортировки.
- **Во время автосейва индустрия стоит** (`server.pauseindustrialduringsave`).
- **Строгий режим делает деление неровным.** Если прогон конвейера длится ≥ 1,5 мс,
  на 120 с включается режим с переносом незаконченной работы на следующий тик.
- **Трубы режутся при смене модели стены или треугольной крыши**, если объём блока
  задевает трубу (`BuildingBlock.CheckForPipes`). Квадратной крыши этот флаг в префабах
  не касается.
- **Трубу нельзя провести через торговый автомат**, но можно через двери и другие деплои
  (`WireTool.VerifyLineOfSight`).
- **Max и Min работают «на каждый контейнер»**, а не на сумму по сети.
- **Буферы конвейера не сохраняются** и сбрасываются при выключении.
- **Конвейер не «видит» сквозь другой конвейер** — цепочки конвейеров не удлиняют сеть.

## Числа и настройки

| Что | Значение | Где |
|-----|----------|-----|
| Порог строгого режима | 3 × 0,5 = 1,5 мс | `industrialFrameBudgetMs × 3` |
| Длительность строгого режима | 120 с | `strictModeUntil = 120f` |
| Лимит фильтров | 30 записей (RPC читает до 60) | `RPC_ChangeFilters` |
| Сортировка: свой список | до 64 записей по 64 символа | `SortSettings.LoadFrom` |

## На практике

- Не надейтесь, что «Min» по категории защитит запас в ящике, если получатель — печь
  или крафтер. Ставьте Min на конкретные предметы.
- Для сигналов «пусто/не пусто» используйте режим «Любой», а не «Не».
- Ставьте конвейер и крафтер за дверь: переключить их можно без прав в шкафу.
- После вайпа или рестарта проверьте крафтеры: если питание моргнуло, они выключены.
