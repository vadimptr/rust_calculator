## Кратко

Все игровые хранилища — маленький и большой ящик, шкафчик, холодильник, тайник, печи,
верстак — наследуют `StorageContainer`. Это `DecayEntity`, поэтому они подвержены
распаду ([[decay]]). Число слотов, разрешённые предметы и доля «сгорающего» при уничтожении
лута задаются полями префаба. Значения конкретных хранилищ — в таблице ниже. Распространённое
мнение «12 слотов у маленького ящика» устарело: в префабе их 18.

## Характеристики

| Поле `StorageContainer` | По умолчанию | Смысл |
|-------------------------|--------------------|-------|
| `inventorySlots` | 6 | Число слотов |
| `maxStackSize` | 0 (без ограничения) | Максимальный стак внутри |
| `dropsLoot` | true | Выпадает ли содержимое при уничтожении |
| `dropLootDestroyPercent` | 0 | Какая доля содержимого уничтожается при смерти |
| `isLockable` | true | Можно ли повесить замок |
| `onlyOneUser` | false | Может ли лутать только один игрок одновременно |
| `needsBuildingPrivilegeToUse` | false | Нужно ли право строительства |
| `allowedItems` / `blockedItems` / `onlyAcceptCategory` | — | Фильтры предметов |

### Значения из префабов

| Хранилище (префаб) | Слотов | HP | Защита | Замок | Шкаф без замка (`requireAuthIfNotLocked`) |
|--------------------|--------|----|--------|-------|-------------------------------------------|
| Маленький ящик (`woodbox_deployed`) | 18 | 150 | `DeployableWood` | да | да |
| Большой ящик (`box.wooden.large`) и его скины, гроб (`coffinstorage`) | 48 | 300 | `DeployableWood` | да | да |
| Бочки и промышленные хранилища (`storage_barrel_b/c`, `industrial_storage_*`, `wicker_barrel`, `bamboo_barrel` и т. п.) | 48 | 300 | `DeployableWood` | **нет** | да |
| Ящики-витрины (`component.box.*.large`) | 48 | 300 | `DeployableWood` | да | да |
| Шкафчик (`locker.deployed`) | 42 | 500 | `DeployableWood` | да | да |
| Холодильник (`fridge.deployed`) | 48 | 200 | `DeployableWood` | да | да |
| Мини-холодильник (`minifridge.deployed`) | 18 | 100 | `DeployableWood` | да | да |
| Тайник (`small_stash_deployed`) | 6 | 150 | `DeployableWood` | нет | нет |

`dropLootDestroyPercent` у всех ящиков 0: при уничтожении всё содержимое выпадает. Среди
хранилищ ненулевое значение только у торгового автомата (`vendingmachine.deployed`, 0,5).
`needsBuildingPrivilegeToUse` и `onlyOneUser` у ящиков выключены. Защиты — в
[[data-protection]], полный список HP — в [[data-entity-health]].

### Особые хранилища

| Объект | Особенность | Где |
|--------|-------------|-----|
| Ящики (`BoxStorage`) | На них можно ставить дочерние деплои; пока они есть, ящик нельзя подобрать | `BoxStorage` |
| Холодильник (`Fridge`) | 5 ед. энергии (мини-холодильник 2); запитанный **полностью останавливает** порчу еды: в префабах `PoweredFoodSpoilageRateMultiplier` = 0 (по умолчанию 0,1) | `Fridge.PowerConsumption`, `PoweredFoodSpoilageRateMultiplier` |
| Тайник (`StashContainer`) | Прячется в землю; открывается в 3 м при взгляде прямо на него | `StashContainer.PlayerInRange` |

## Поведение

### Доступ

`StorageContainer.CanBeLooted`: если в префабе `needsBuildingPrivilegeToUse`, нужен доступ
к шкафу ([[building-privilege]]). Если включён ConVar `storagecontainer.canRequireAuthIfNoLock`
и у префаба `requireAuthIfNotLocked`, хранилище **без замка** тоже требует авторизации
в шкафу. Хранилище с замком открывается по правилам замка.

### Уничтожение

`StorageContainer.OnDied` → `DropItems`:

- если в контейнере один предмет — он выпадает отдельно;
- иначе появляется мешок `item_drop` (на воде — плавучий), в который переносится
  `1 − DestroyLootPercent` содержимого. Стаки урезаются пропорционально, дробные
  остатки разыгрываются случайно (`ItemContainer.RemoveFractionOfContainer`);
- ящик (`BoxStorage`) кладёт мешок в ближайшую к себе точку **в сторону последнего
  атакующего** (`LastAttackedDir` — направление от ящика к нему).

Если включён `storagecontainer.dropCorpseOnDeath` (по умолчанию false), вместо мешка
может появиться «труп» хранилища, сохраняющий `corpseItemsSavedPercent` (0,5) содержимого.
Труп не появляется, если хранилище погибло от распада или его сломал владелец / игрок с
доступом к шкафу.

### Тайник

- Спрятанный тайник (`Flags.Reserved5`) через 3 с перестаёт передаваться клиентам по сети.
- Открыть его можно, стоя ближе 3 м и глядя почти точно на него
  (скалярное произведение направления взгляда > 0,95).
- Переключать «спрятан/открыт» можно не чаще раза в 3 с.
- Через 259 200 с (3 суток) после последнего переключения тайник распадается
  (`StashContainer.Decay`).
- Если над тайником в пределах 5 м появилась постройка (слой Construction), он выбрасывает
  содержимое и уничтожается (`DoOccludedCheck`).

## Числа и настройки

| ConVar | По умолчанию | Смысл |
|--------|--------------|-------|
| `storagecontainer.canRequireAuthIfNoLock` | false | Хранилища без замка требуют шкафа (если разрешено префабом) |
| `storagecontainer.dropCorpseOnDeath` | false | «Труп» хранилища вместо мешка |
| `storagecontainer.corpseItemsSavedPercent` | 0,5 | Доля содержимого, сохраняемая в «трупе» |
| `server.itemdespawn` | 300 с | База времени жизни выпавших предметов |
| `server.itemdespawn_container_scale` | 2 | Множитель для мешков |
| `server.dropitems` | true | Выпадают ли предметы вообще |

Мешок без расчёта по предметам живёт `itemdespawn × 16 × itemdespawn_container_scale`
= 9600 с; с расчётом по предметам — по самому «долгоживущему» предмету внутри
(`DroppedItemContainer.CalculateRemovalTime`). Режим задан полем `ItemBasedDespawn`: у мешка от
ящика (`item_drop`, до 48 предметов) и плавучего мешка (`item_drop_buoyant`, до 42) он выключен —
они живут 9600 с (2 ч 40 мин); у рюкзака (`item_drop_backpack`) включён.
Пока мешок открыт, таймер исчезновения перезапускается.

## Нюансы

- **Мешок падает к рейдеру.** У ящиков точка выпадения сдвигается на 10 м в сторону последнего
  атакующего и затем прижимается к ближайшей точке ящика. Лут оказывается с той стороны,
  откуда ломали.
- **Один предмет — без мешка.** Если в контейнере ровно один предмет, он вываливается
  как обычный предмет, без мешка.
- **Не всё долетает — только у торгового автомата.** Если у префаба задан
  `dropLootDestroyPercent`, эта доля стаков уничтожается при смерти контейнера. Из хранилищ это
  только торговый автомат (половина содержимого); ящики, шкафчики и холодильники отдают всё.
- **Тайник ломается постройкой.** Поставить фундамент над чужим тайником — значит
  вскрыть его: содержимое выпадет.
- **Спрятанный тайник не существует для клиентов.** Через 3 с после закапывания сервер
  перестаёт сообщать о нём игрокам (`limitNetworking`) — клиент узнаёт о тайнике, только
  когда его раскопают.
- **Предметы из исчезнувшего мешка могут быть «закопаны».** Если в префабе мешка
  включён `buryLeftoverItems`, при исчезновении предметы регистрируются в `BuriedItems` —
  системе находок металлоискателя. Флаг стоит только у выпавшего рюкзака
  (`item_drop_backpack`); мешки от ящиков просто исчезают.

## На практике

- Ломая ящик, стойте с той стороны, где удобно подобрать мешок: он появится у грани ящика,
  обращённой к вам, а не застрянет за ним в стене.
- Тайники прячьте подальше от мест, где кто-то может строить.
- Если сервер включил `canRequireAuthIfNoLock`, ящики без замков всё равно защищены шкафом.
