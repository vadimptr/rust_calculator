## Кратко

Общей защиты от петель в электросети нет. Петлю ищут только четыре элемента: сумматор, OR,
XOR и ячейка памяти. Каждый — своим способом, на ограниченную глубину. Остальные элементы
петли не замечают. Петля, которая проходит через сигнальный (неосновной) вход, не видна никому.

«Короткое замыкание» в Rust ничего не ломает и не наносит урона. Элемент просто обнуляет
вход и, у некоторых, зажигает флаг `Reserved7` (`IOEntity.Flag_ShortCircuit`) — индикатор
на модели.

## Как работает

### Обход вверх: IsConnectedTo

```
IsConnectedTo(цель, глубина, defaultReturn):
    если глубина ≤ 0: вернуть defaultReturn
    для каждого ОСНОВНОГО входа (mainPowerSlot):
        сосед = кто подключён
        если сосед == цель → true
        если сосед.IsConnectedTo(цель, глубина − 1) → true
    вернуть false
```

- Идёт **вверх** по проводам, только через входы с `mainPowerSlot`.
- Ветвится: проверяет все основные входы каждого предка.
- `defaultReturn` — что вернуть, если глубина кончилась раньше, чем цепочка.

### Кто проверяет и как

| Элемент | Когда | Глубина | Если глубина кончилась | Что делает при петле |
|---|---|---|---|---|
| Сумматор (`ElectricalCombiner`) | вход > 0 | `backtracking × 2` = 16 | считает петлёй (`defaultReturn: true`) | вход = 0, флаг `Reserved7` |
| OR (`ORSwitch`) | любой вход | `backtracking` = 8 | не петля | вход = 0, флага нет |
| XOR (`XORSwitch`) | вход > 0 | 8 | не петля | вход = 0, флаг `Reserved7` |
| Ячейка памяти (`ElectricalDFlipFlop`) | любой вход | 8, вниз по выходам (`OutputsConnectedTo`) | не петля | **все** входы = 0, флаг `Reserved7`, если ≥ 2 выходов ведут обратно |

`ioentity.backtracking` по умолчанию 8 (ConVar).

### Ячейка памяти: обход вниз

`DetectShortCircuit` для каждого выхода вызывает `OutputsConnectedTo(this, 8, …)`. Этот обход
идёт **вниз по всем выходам** всех устройств, в том числе в неосновные входы. Замыкание
засчитывается, только если **оба** выхода ячейки возвращаются в неё саму. Тогда обнуляется
любой входящий сигнал, включая питание.

Одна обратная связь (например, Output → … → Reset) разрешена: это нормальная схема «сработал
и сбросился».

## Нюансы

### Ложные замыкания у сумматора

Сумматор проверяет петлю с `defaultReturn: true`. Если цепочка основных входов выше него
содержит 16 устройств и больше (считая от ближайшего), проверка исчерпает глубину и сочтёт это
петлёй. Вход обнуляется, горит флаг замыкания.

Обход проходит **сквозь батареи**: у батареи вход «Power In» основной. Поэтому в цепочку
считаются и устройства, которые заряжают батарею. Пример: сумматор ← батарея ← 15 сплиттеров
← панель. Петли нет, но сумматор покажет замыкание.

Флаг `Reserved7` у сумматора отражает только **последний** обновлённый вход: при
обновлении другого входа без петли он сбрасывается.

### Что не защищено

- **Блокировщик.** Вход Block не основной и петли не проверяет. Отсюда
  [[flicker|осциллятор]] «блокировщик сам себя блокирует».
- **AND.** Проверки нет вовсе.
- **Сплиттер, ветвитель, выключатели, таймер, счётчик, кабельный туннель, RF** — проверки нет.
- **Любая петля через неосновной вход** (Toggle, Set, Reset, Switch On/Off, Increment,
  Block) невидима для `IsConnectedTo`.
- **Батарея, заряжающая сама себя.** Петля «выход батареи → … → вход батареи» разрешена.
  Чистого выигрыша она не даёт: заряд идёт с КПД 0.8, а расход (`GetDrain`) включает саму
  батарею как потребителя. Батарея медленно разряжается. Исключение — режим мерцания,
  см. [[flicker]].

### Что происходит в незащищённой петле

Петля не «зависает» и не роняет сервер. `IOEntity.UpdateOutputs` толкает значения не чаще раза
в `responsetime` на устройство, а очередь за кадр проходит один круг ([[io-engine]]).

- **Петля, которая меняет своё состояние** (инвертирующая, как блокировщик), — это генератор
  колебаний. Все устройства в ней и после неё переходят в режим мерцания.
- **Петля без инверсии** стабилизируется: значения доходят до постоянных и больше не меняются.
  Устройства с потреблением 1 по кругу уменьшают значение на 1 за проход.
- Служебные обходы (`SendChangedToRoot`, расход батареи `AddConnectedRecursive`) хранят
  список посещённых, поэтому в петлях не зацикливаются.

## На практике

- Если сумматор горит красным без видимой петли, сократите цепочку выше него (включая
  цепочку, которая заряжает батарею на его входе) до 15 устройств и меньше.
- Для обратной связи в логике используйте неосновные входы: Reset, Toggle, Block. Их петли
  сервер не обнуляет.
- У ячейки памяти не заводите оба выхода обратно в саму ячейку, даже через длинную логику.
