## Кратко

[[recycler|Переработчик]] разбирает предмет «обратно» по его рецепту крафта. Выход по каждому
ингредиенту — количество из рецепта, делённое на `amountToCreate` и умноженное на
эффективность. Дробные остатки разыгрываются случайно, так что в среднем вы получаете ровно
эту долю. Скрап считается отдельно через поле рецепта `scrapFromRecycle`.

Эффективность и длительность тика задаёт файл настроек
`assets/prefabs/deployable/recycler/config/recyclerconfig.asset` — для трёх типов переработчика
(зелёный, жёлтый, красный).

## Как работает

### Что можно переработать

`Recycler.CanBeRecycled`: у предмета есть рецепт (`info.Blueprint != null`) и он не еда
(`category != Food`). Всё. Предметы без рецепта (руда, ресурсы, большинство лута без крафта)
в переработчик не положить: входные слоты 0–5 принимают только перерабатываемое, выходные
6–11 — что угодно.

### Тик

`StartRecycling` берёт из конфига эффективность и длительность (`GetRecyclerStats`) и
запускает `RecycleThink` каждые `duration` секунд. За один тик:

1. Берётся **первый** перерабатываемый стак во входных слотах 0–5. Остальные ждут.
2. Сколько штук разобрать за тик:
   ```
   n = 1, если в стаке 1 штука
   n = ceil(min(amount, MaxStackable * 0.1)), иначе
   ```
   То есть до 10 % максимального стака за тик.
3. Эффективность с учётом прочности:
   ```
   eff = efficiency
   если у предмета есть прочность:
       eff = clamp01(eff * clamp(condition/maxCondition * maxCondition/max, 0.1, 1))
   ```
   Второй множитель — это текущая прочность относительно **заводского** максимума,
   поэтому учитывается и износ, и потеря максимальной прочности от ремонтов ([[item-condition]]).
4. **Скрап**, если `scrapFromRecycle > 0`:
   ```
   scrap = scrapFromRecycle * n
   если предмет нестакуемый и с прочностью: scrap *= condition/maxCondition
   scrap *= eff / 0.5
   ```
   Целая часть выдаётся сразу, дробная копится в `scrapRemainder` переработчика и
   выдаётся, когда наберётся единица.
5. Стак уменьшается на `n`.
6. **Ингредиенты**: для каждого ингредиента рецепта, кроме скрапа,
   ```
   x = amount / amountToCreate * eff * n
   выход = floor(x) + (1 с вероятностью дробной части x)
   ```
   Ингредиенты, запрещённые в текущей эпохе (`EraRestriction.Recycle`), не выдаются.
7. Если выход некуда положить — предмет бросается на землю над переработчиком
   (+2 м по высоте), и переработчик **останавливается**. Он также останавливается, когда
   перерабатывать больше нечего.

### Типы переработчиков и энергосеть

`RecyclerConfig.RecyclerType`: `Green`, `Yellow`, `Red`. Тип задан в префабе, но
`GetRecyclerType` превращает жёлтый в зелёный, если переработчик **не в безопасной зоне** ([[safe-zones]]).
Безопасная зона определяется по триггеру `TriggerSafeZone` в радиусе 1 м
(`Recycler.IsInSafeZone`); зона с активным боем (`TriggerSafeZoneOverride.IsCombatActive`)
не считается безопасной.

Значения `RecyclerConfig` (`recyclerTypeConfigs`):

| Тип (префаб) | Эффективность | Тик, с | С энергосетью | Скрап от `scrapFromRecycle` |
|--------------|---------------|--------|---------------|-----------------------------|
| `Green` (`recycler_static`, обычный на монументах) | 0,5 | 5 | со стадии 2 — эффективность 0,6, со стадии 4 — тик 4,5 с | ×1 (×1,2 со стадии 2) |
| `Yellow` (`recycler_static_yellow`, безопасная зона) | 0,4 | 8 | не влияет | ×0,8 |
| `Red` (`recycler_static_red`) | 0,75 | 4 | **требует** стадию 4 (`requiredPowergridStageToUse`) | ×1,5 |

Красный переработчик без питания 4-й стадии не включается, но при `powergrid.enabled = false`
работает без ограничений (см. ниже). Поля конфига:

| Поле конфига | Смысл |
|--------------|-------|
| `efficiency`, `duration` | Базовые эффективность и длительность тика |
| `requiredPowergridStageToUse` | Минимальная стадия энергосети, без которой переработчик не включается |
| `efficiencyBuffPowergridStage`, `powergridEfficiency` | С какой стадии и до какой эффективности растёт выход |
| `durationBuffPowergridStage`, `powergridDuration` | С какой стадии тик становится короче |

Стадия энергосети приходит от системы `Powergrid` (электростанция с тяжёлыми
предохранителями). Если `powergrid.enabled = false`, стадия считается 0, и переработчик,
которому нужна сеть, всё равно работает (`GetRecyclerState` проверяет `Powergrid.enabled`).
Для зелёного переработчика стадию полной эффективности можно переопределить ConVar
`powergrid.greenRecyclerFullEfficiencyStage`.

### Переработка прямо в инвентаре

Некоторые предметы имеют `ItemModRecycleInto`: команда `recycle_item` превращает предмет
в `numRecycledItemMin..numRecycledItemMax` штук другого предмета без переработчика.
Какие предметы это умеют — задано у самих предметов.

## Числа и настройки

| Что | Значение | Где |
|-----|----------|-----|
| Входные / выходные слоты | 0–5 / 6–11 | `Recycler.HasRecyclable`, `MoveItemToOutput` |
| Штук за тик | `ceil(min(amount, MaxStackable × 0,1))` | `Recycler.RecycleThink` |
| Нормировка скрапа | `scrapFromRecycle` дан для эффективности 0,5 | `num / 0.5f` в `RecycleThink` |
| Минимальный множитель прочности | 0,1 | `RecycleThink` |
| Эффективность, длительность тика | зелёный 0,5 / 5 с, жёлтый 0,4 / 8 с, красный 0,75 / 4 с | `RecyclerConfig` |
| `powergrid.enabled` | true | `Powergrid` |
| `powergrid.greenRecyclerFullEfficiencyStage` | −1 (не переопределять) | `Powergrid` |

Обычный (зелёный) переработчик возвращает **50 %** ингредиентов, а с энергосетью стадии 2 и
выше — 60 %. Отсюда и «около 60 %» из опыта игроков. Переработчик в безопасной зоне (жёлтый)
возвращает 40 % и работает медленнее (8 с на тик против 5 с). Красный — 75 % за 4 с, но только
при питании от энергосети 4-й стадии.

## Нюансы

- **Скрап задан «на 50 %».** Множитель `eff / 0.5` означает: `scrapFromRecycle` из рецепта —
  это выход при эффективности 0,5, то есть ровно у зелёного переработчика. У жёлтого скрапа на
  20 % меньше, у зелёного с бустом сети (0,6) — на 20 % больше, у красного — в 1,5 раза больше.
- **Износ бьёт по скрапу дважды.** У нестакуемого предмета с прочностью скрап умножается и на
  `eff` (куда уже вошла прочность), и ещё раз на `condition/maxCondition`. Предмет на 50 %
  прочности даёт примерно четверть скрапа от нового.
- **Ремонт портит переработку.** В множитель эффективности входит `maxConditionNormalized`.
  Предмет, который много раз чинили, перерабатывается хуже, даже будучи «полным».
- **Минимум 10 % эффективности.** Даже сломанный в ноль предмет даёт хотя бы
  `efficiency × 0,1` от ингредиентов.
- **Время зависит от размера стака, а не от предмета.** За тик уходит до 10 % максимального
  стака. Стак любого размера, заполненный до максимума, разбирается примерно за 10 тиков.
  Нестакуемые предметы идут по одному за тик.
- **Обрабатывается один слот за тик.** Раскладывать предметы по шести слотам бесполезно
  для скорости: переработчик всё равно идёт по слотам по очереди.
- **Остаток скрапа живёт в переработчике.** `scrapRemainder` — поле самого переработчика.
  Дробная часть, накопленная вами, достанется следующему, кто им воспользуется. Поле не
  сохраняется в сейв.
- **Скрап из рецепта не возвращается.** Ингредиент «скрап» пропускается: если предмет
  крафтится за скрап, вернётся только `scrapFromRecycle`.
- **Переполнение = остановка.** Когда выход полон, лишний предмет падает на землю,
  а переработчик выключается.
- **Жёлтый вне зоны — зелёный.** Если безопасную зону отключить (или режим игры её убирает),
  переработчик автоматически работает по параметрам зелёного типа.

## На практике

- Перерабатывайте предметы целыми: каждая потеря прочности уменьшает и ресурсы, и скрап.
- Не держите выход переработчика забитым: переработчик выключится, а предметы окажутся
  на земле, где их подберёт кто угодно.
- Мелкие дробные остатки скрапа выгоднее «добирать» одной большой партией на одном
  переработчике.
